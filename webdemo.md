# Web Demo: slitdec in the Browser via Emscripten

`demo/` contains a static (no backend) web page that runs the slitdec
extraction in the browser: pick a sample swath or upload one, adjust
parameters with sliders, and watch data / model / residual / spectrum /
slit function update live.

Live at: **https://ivh.github.io/CharSlit/**

## Why this works well for CharSlit

- `slitdec.c` is plain C99: no BLAS/LAPACK, no OS deps, only libc/math.
  Compiled directly with emcc, the wasm module is ~24 KB and loads
  instantly. No Python involved.
- The library is **single-threaded by design** (commit 7121310 removed
  threading). This matters: pthreads in wasm require SharedArrayBuffer,
  which forces COOP/COEP hosting headers. Single-threaded C is the wasm
  happy path and works on any static host, including GitHub Pages.

Scope note: real users run CharSlit in local pipelines. The demo is
teaching/outreach/paper-supplement material, not something science users
need. An alternative route — a PEP 783 Pyodide wheel + JupyterLite for a
full Python-API-in-browser story — was considered and remains cheap to
add later (one CI job), but wasn't pursued: ~20+ MB initial download and
Emscripten wheels are pinned to a Pyodide ABI version.

## Architecture

```
demo/
  demo_api.c        C shim wrapping slitdec() for the JS side
  build.sh          emcc build -> slitdec.mjs + slitdec.wasm (gitignored)
  index.html        page skeleton
  style.css
  app.js            UI: sliders, canvas plots, upload, swath dropdown
  worker.js         web worker owning the wasm module and current image
  io.js             minimal FITS and .npy readers
  make_golden.py    golden reference generator (runs native charslit)
  check_golden.mjs  correctness gate: wasm vs native comparison
  make_manifest.py  builds swaths.json for the sample-swath dropdown
  deploy.sh         rebuild + force-push site to the gh-pages branch
```

### C shim (`demo_api.c`)

One exported function, `demo_extract`, so JS does not replicate setup
logic. It builds what the nanobind wrapper would: constant
`ycen[ncols] = ycen_frac`, uniform slitcurve `[0, c1, c2, 0, 0, 0]` for
every column (a deliberate simplification vs. real data where c1/c2 vary
with x — the right trade for slider-driven exploration), zero slitdeltas
(length ny), `mask[i] = isfinite(im[i])`, seeds `sP = 1`,
`sL = 1/osample`, zeroes model/unc, then calls `slitdec` with
`use_preset = 0`. The mask is an output too: it shows kappa rejection.

JS allocates im/sP/sL/model/unc/info/mask via `_malloc` and reads results
from the wasm heap (`HEAPF64`, `HEAPU8`).

### Build

Requires emsdk (`brew install emscripten` on macOS):

```sh
./demo/build.sh
```

Plain emcc, no CMake: `-sMODULARIZE -sEXPORT_ES6 -sALLOW_MEMORY_GROWTH`,
exporting `_demo_extract,_malloc,_free` and the heap views. No pthread
flags (see above), no `-lm` needed with emcc.

### Web worker

The solver runs in a web worker: wasm is ~2x slower than native and
uploads can be full frames (a 2048x2048 CRIRES frame solves in ~350 ms),
so the worker keeps sliders responsive and isolates a wasm abort from
killing the page. The worker owns the wasm module and the current image
(sent once per load); slider changes only ship parameters. The main
thread debounces slider input, keeps at most one solve in flight, and
drops stale replies by sequence number.

**GOTCHA — module workers and top-level await.** The worker must assign
`onmessage` synchronously and buffer a backlog until the wasm module
resolves. With top-level `await`, messages posted while the module is
still loading are dispatched before `onmessage` exists and are silently
dropped — this cost a debugging session. Also: re-acquire `HEAPF64`/
`HEAPU8` views after each call; `ALLOW_MEMORY_GROWTH` invalidates old
views when the heap grows.

### Correctness gate

The demo is trustworthy rather than decorative: `make_golden.py` runs
native `charslit.slitdec` on three synthetic cases (flat fast path;
curved with outliers and NaNs; smoothed with kappa off) and dumps
inputs + outputs to `demo/golden.json` (NaN encoded as JSON null).
`check_golden.mjs` feeds the same inputs to the wasm module and
compares at rtol 1e-8 — in practice clang vs emscripten-clang agree to
~1e-15, and the output masks match exactly.

```sh
uv run python demo/make_golden.py
node demo/check_golden.mjs
```

Rerun this gate after any change to `slitdec.c` or the shim.

### Inputs

- **Built-in synthetic swath** (400x48), generated in JS on page load:
  Gaussian slit profile x spectrum with emission lines, curvature
  c1=-0.03, c2=0.0015 baked in and the sliders defaulting to those
  values — drag away from truth and the residual panel lights up. Eight
  hot/cold pixels for the kappa slider to eat, two NaN pixels.
- **Sample-swath dropdown**, fed by `swaths.json` (generated by
  `make_manifest.py`, gitignored): the repo's `data/*.fits` swaths with
  representative uniform-curvature defaults — median c1/c2 of the
  per-column `curvedelta_*.npz` fit and the fractional part of ycen.
  Selecting a swath snaps the sliders to the fitted values. Files
  without a curvature fit load with zeros and are labeled as such.
  Uniform sliders cannot reproduce per-column curvature, so wide real
  swaths (CRIRES) extract imperfectly — expected and honest.
  CRIRES_UNE_J (200 MB full frame) is excluded from the manifest.
  Locally the dropdown needs the `demo/data -> ../data` symlink; it
  hides itself if `swaths.json` is absent.
- **FITS / .npy upload** (`io.js`): 2880-byte header blocks, BITPIX
  8/16/32/-32/-64, BSCALE/BZERO, big-endian; primary HDU if it has data,
  else the first 2D image extension (matches conftest behavior for
  multi-extension ESO/CRIRES files). `.npy` accepts 2D arrays of common
  dtypes, C or Fortran order, either endianness. NaNs become masked
  pixels; size cap 2048x2048. Parsers are verified against
  astropy/numpy. Uploads reset the curvature sliders to zero (pitched
  as flattish swaths).

### Plots (pure canvas, no libraries)

Full-width panels: data, model, residual (symmetric diverging scale),
then spectrum with a +/-1 sigma band from `unc` and the slit function
vs. spatial position in detector pixels (iy/osample). Viridis-style LUT
with 1-99 percentile scaling; masked/rejected pixels tinted red in the
data panel; NaN gray elsewhere. Row 0 is drawn at the bottom (astronomy
convention). Hover over an image panel for a per-pixel
data/model/residual readout. The status bar decodes `info` (status,
iterations, delta_x) and shows solve wall time and rejected-pixel count.

## Local development

```sh
./demo/build.sh                          # rebuild wasm after C changes
uv run python demo/make_manifest.py      # refresh swaths.json (needs data/)
ln -sfn ../data demo/data                # once, for the dropdown
python3 -m http.server -d demo 8000      # serves .wasm with correct MIME
```

## Deployment

```sh
./demo/deploy.sh
```

Rebuilds, regenerates the manifest, assembles the static site (page +
wasm + manifest + the sample FITS, ~14 MB) in a temp dir and force-pushes
it as an orphan commit to the `gh-pages` branch, which GitHub Pages
serves at https://ivh.github.io/CharSlit/. The site history is
disposable; master is never touched. Pages deployments occasionally fail
with a generic "try again later" — rerun the failed job
(`gh run rerun <id> --failed`).

## Out of scope (v1)

- slitdeltas (zero in the demo)
- `preset_slitfunc` / single-pass mode
- per-column varying slitcurve
- Pyodide/PEP 783 wheel + JupyterLite (see above)
